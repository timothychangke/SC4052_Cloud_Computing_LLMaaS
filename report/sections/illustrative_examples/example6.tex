The sixth example demonstrates the image-generation pathway, in which the
pipeline intercepts a creative image prompt, identifies a matching sponsored
product, and rewrites the prompt so that the product appears naturally within
the generated scene.  Figure~\ref{fig:example-6} shows the result: a
photorealistic sunrise trail image in which the runner is visibly wearing the
Nike Pegasus~41.

\subsubsection{Stage 1: Context Extraction}
\label{subsubsec:example6-context}

The user submits a short creative prompt:
\emph{``A runner training at sunrise on a mountain trail''}.
The context-extraction module classifies the request as an image-generation
query and identifies its commercial relevance:

\begin{lstlisting}[style=jsonstyle, caption={Context extraction output for
the image-generation query.}, label={lst:example6-context}]
{
  "intent":          "image_generation",
  "ad_receptivity":  "medium",
  "purchase_signal": 0.75,
  "topics":          ["running", "trail running", "outdoor fitness"],
  "entities":        []
}
\end{lstlisting}

\noindent
A \texttt{purchase\_signal} of~0.75 and \texttt{ad\_receptivity} of
\texttt{medium} place the request on the commercial path.  The
\texttt{image\_generation} intent routes the request to the image-generation
handler rather than the text-synthesis handler, but the downstream ad-matching
logic is identical.

\subsubsection{Stage 2: Vector Search and Ad Matching}
\label{subsubsec:example6-retrieval}

The topics \emph{``running trail running outdoor fitness''} are encoded into a
dense vector and searched against the ad inventory.  The Nike Pegasus~41
returns the highest cosine similarity, well above the acceptance threshold:

\begin{lstlisting}[style=jsonstyle, caption={Top vector-search candidate for
the image query.}, label={lst:example6-retrieval}]
{
  "ad_id":             "ad_nike_pegasus_41",
  "product_name":      "Nike Pegasus 41",
  "similarity":        0.8124,
  "bid_cpm":           5.00,
  "daily_budget":      100.00,
  "today_spend":       12.40,
  "product_image_url": "https://assets.example/nike_pegasus_41.png"
}
\end{lstlisting}

\noindent
The presence of a \texttt{product\_image\_url} field signals to the handler
that an image-edit call is available as a grounded alternative to a plain
text-to-image call.  The budget gate confirms that the remaining daily budget
is sufficient, so the ad passes to the prompt-rewriting stage.

\subsubsection{Stage 3: Prompt Rewriting}
\label{subsubsec:example6-prompt}

The image-generation handler invokes the prompt-rewriter module, which
receives the user's original prompt and the winning ad's structured fields.
The rewriter's task is to produce an enhanced prompt that retains the user's
intended scene while incorporating the sponsored product in a visually
natural, diegetic manner.  The rewritten prompt returned for this request is:

\begin{quote}
\emph{A runner laces up their Nike Pegasus~41 shoes, preparing for a training
session at sunrise on a mountain trail.  The shoes are a perfect fit for this
daily run, with the lightweight design and responsive ZoomX foam ready to
tackle the easy to moderate miles ahead.  As the runner takes their first
steps, the warm sunrise light casts a glow on the trail, illuminating the
winding path and the majestic mountains in the background.  The runner's
breath is visible in the cool morning air as they begin their journey, the
Nike Pegasus~41 shoes making every step feel effortless and natural.  The
trail stretches out before them, inviting the runner to explore and push their
limits.}
\end{quote}

\noindent
The rewriter inserts the product name twice, connects the product's key
features (ZoomX foam, lightweight design) to the scene's physical context,
and frames both references as incidental details rather than promotional
claims---consistent with the diegetic-placement objective.

\subsubsection{Stage 4: Image Generation and Impression Logging}
\label{subsubsec:example6-response}

The rewritten prompt is forwarded to the image-generation endpoint.  When a
\texttt{product\_image\_url} is available the handler issues an
\texttt{images.edit} call, supplying the product photo as a reference anchor
so that the model can ground the shoe's appearance on the actual product
rather than a hallucinated approximation.  The endpoint returns a base64-encoded
image delivered as a data URI, accompanied by the ad metadata (product name,
tracking URL, and disclosure label) so that the frontend can render the
\textsc{[Sponsored]} overlay alongside the image.

Once the image is returned, the orchestrator fires the same two asynchronous
writes used in the text pathway: an impression event appended to the
\texttt{events} table, and a \texttt{daily\_spend\_log} upsert that
increments \texttt{spend} by $\text{bid\_cpm}/1000 = \$0.005$.  If no ad
had passed the similarity threshold, the handler would have fallen back to a
plain \texttt{images.generate} call with the user's original, unmodified
prompt, producing an unsponsored image with no impression recorded.
